# Lathe: build state

The single ledger for this build. Every session reads this first, completes the
next item, then updates the table. The design lives in `docs/design/`; this file
tracks what exists.

## What this is

Lathe is a course you complete by making a coding-agent harness work, plus the
local tool that grades it. No cloud runner, no account, no API key, Go only.

- Binary: `lathe` (`cmd/lathe`)
- Module: `lathe`
- Learner edits: `harness/` only
- Truth for "done": `chapters/NN-*/checks/*_test.go`

## Locked decisions

Settled. Reopen only if a test proves them wrong.

| # | Decision | Why |
|---|---|---|
| 1 | Reference first, then subtract. `solutions/chNN` is the harness after chapter NN. | Invariants are found by building. Deletion is cheap; retrofitting costs a rewrite of chapters a learner already passed. |
| 2 | Chapters are cumulative and monotonic. Chapter NN+1 adds to chapter NN. | One artifact per chapter, and "prior chapters stay green" becomes a guarantee. |
| 3 | Grade behaviour at the seam: requests, events, files, exit codes. Never file layout or function names. | The reference is an oracle, not a mold. A different internal design that satisfies the claims passes. |
| 4 | Models are scripted. `internal/fake` is a real HTTP server speaking real SSE. | Offline, instant, free, byte-precise. No live mode gates progress. |
| 5 | Eleven core chapters, MCP as advanced, plus a "where next" page. | pi parity is out of scope. The machine is the subject. |
| 6 | Prose follows `docs/writing-style.md`. | Human technical writing. No AI tells. |
| 7 | Three documents per chapter: `overview.md`, `problem.md`, `example.md`. | Three jobs, read at three times. |
| 8 | The site renders the same markdown. Generated by `lathe site`. | One source of truth. |
| 9 | A build error is "not ready", never a failed case. | The biggest UX win over raw `go test`. |
| 10 | `lathe verify` proves each chapter rejects its "before" state and accepts its "after" state. | Catches green-on-nothing, the worst grader bug. |
| 11 | The pre-chapter state is derived from the previous solutions, never stored. | `stubs/` drifted. One artifact cannot drift from itself. |
| 12 | Later chapters add files; they do not rewrite `loop.go`. | A chapter that rewrites the core is a design failure, and it makes the course expensive to build. |

## Harness seam design

Chapter 04 is written once, against these interfaces, so chapters 05 to 11 only
add files. A chapter that modifies `loop.go` is a design failure.

| Seam | Signature | Implemented by |
|---|---|---|
| `Provider` | `Chat(ctx, Request) (Message, Usage, error)` | ch01, extended ch02 |
| `Tool` | `Name`, `Description`, `Schema`, `Execute(ctx, json.RawMessage) (ToolResult, error)` | ch03 |
| `Contributor` | `Contribute(ctx) (string, error)`, appended to the system prompt | ch05 AGENTS.md, ch09 skills |
| `Trimmer` | `Fit([]Message, budget int) ([]Message, error)` | ch07 |
| `Steering` | `Drain() []Message`, polled after each tool batch | ch08 |
| `Recorder` | `Append(Event) error`, `Load(id) ([]Message, error)` | ch06 |
| `ToolSource` | `Tools(ctx) ([]Tool, error)`, merged into the registry | ch10 subagent, ch11 MCP |
| `Emitter` | `Emit(Event)` | ch04 |

Only `cmd/harness/main.go` changes across chapters 05 to 11, because it wires the
seams.

## Next actions, in order

1. Write the reference harness through chapter 04 in one pass: provider tool
   folding, tools (read, write, bash), loop with every seam above and the event
   grammar. Land as `solutions/ch02`, `ch03`, `ch04`.
2. Write checks for 02, 03, 04. Each must fail on its derived "before" state.
3. Write `overview.md`, `problem.md`, `example.md` for 01 to 04.
4. Repeat steps 1 to 3 for 05 to 11, one chapter at a time.
5. `lathe site`: static documentation website from the same markdown.
6. Bubble Tea TUI, `lathe watch`, `lathe doctor`.
7. Independent agent run: play the course as a learner, with good and bad code.

## Verification commands

```sh
go build ./... && go vet ./... && go test ./...
go run ./cmd/lathe verify
go run ./cmd/lathe submit 01 --solution
go run ./cmd/lathe site --out site/dist
```

All four must be clean before a chapter is called done.
