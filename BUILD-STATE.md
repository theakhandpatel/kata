# Lathe: build state

The single ledger for this build. Every session reads this first, does the next
unchecked item, then updates the table. Nothing here restates the design; the
design lives in `docs/design/`.

## What this is

Lathe is a course you build by making a coding-agent harness work, and a local
tool that grades it. No cloud runner, no account, no API key. Go only.

- **Binary**: `lathe` (`cmd/lathe`)
- **Module**: `lathe`
- **Learner edits**: `harness/` only
- **Truth for "done"**: `chapters/NN-*/checks/*_test.go`

## Locked decisions

These are settled. Do not reopen them; reopen only if a test proves them wrong.

| # | Decision | Why |
|---|---|---|
| 1 | Reference first, then subtract. `solutions/chNN` is the harness after chapter NN; `stubs/chNN` is the state before it. | Invariants are discovered by building. Deletion is cheap; retrofitting costs a rewrite of chapters a learner already passed. |
| 2 | Chapters are cumulative and monotonic. chN+1's code is a superset of chN's. | Makes `--solution` one artifact, and makes "prior chapters stay green" a guarantee instead of a hope. |
| 3 | Grade behaviour at the seam: requests, events, files, exit codes. Never file layout or function names. | The reference is an oracle, not a mold. A different internal design that satisfies the claims passes. |
| 4 | Models are scripted, always. `internal/fake` is a real HTTP server speaking real SSE. | Offline, instant, free, byte-precise. No live mode gates progress. |
| 5 | Eleven core chapters, plus MCP as an advanced chapter, plus a "where next" page. | pi parity is out of scope. The machine is the subject, not every attachment. |
| 6 | Prose follows the Querylathe house style (`docs/writing-style.md`). No AI vocabulary, no em dash, active voice, you, short sentences. | The user asked for human-readable technical writing. |
| 7 | Three documents per chapter: `overview.md` (how it works), `problem.md` (what is graded), `example.md` (full annotated implementation). | Three different jobs, read at three different times. |
| 8 | The site is a renderer over the same markdown, generated by `lathe site`. No second copy of content. | One source of truth. |
| 9 | A build error is reported as "not ready", never as a failed case. | The biggest UX win over raw `go test`. |
| 10 | `lathe verify` proves each chapter rejects its own stub and accepts its reference. | Catches green-on-nothing, the worst grader bug. |

## Verification commands

```sh
go build ./... && go vet ./... && go test ./...
go run ./cmd/lathe verify
go run ./cmd/lathe submit 01 --solution
go run ./cmd/lathe site --out site/dist
```

All four must be clean before a chapter is called done.
